# מערכת פורומים - שלד קוד מלא

זהו שלד (scaffold) פונקציונלי של המערכת שביקשת, בנוי ב-Next.js (React + API בפרויקט אחד).
הוא רץ **מיד** ללא שום שירות חיצוני, עם נתוני דמו - כדי שתוכל לראות ולבדוק את כל הזרימה.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local   # וערוך את הערכים - לפחות AUTH_SECRET ו-ADMIN_CODE
npm run dev
```
האתר יעלה בכתובת http://localhost:3000

## מה כבר עובד עכשיו (עם נתוני דמו בזיכרון)

- עמוד ראשי עם רשימת פורומים, חיפוש חי, יצירת פורום חדש עם הגדרת רמות הרשאה
- הרשמה/התחברות עם אימייל+סיסמה (מוצפן עם bcrypt), עוגיית התחברות חתומה
- פרופיל אישי: "הפורומים שיצרתי" / "פורומים שאני חבר בהם"
- כניסה לפורום, יצירת נושא חדש ותגובות, עם עורך טקסט עשיר (מודגש/נטוי/קו תחתון/גודל/צבע - בסגנון וורד)
- הרשאות צפייה/עריכה לחברים, והרשאות נפרדות למבקרים (ללא גישה / צפייה בלבד / צפייה ותגובה)
- הזמנת חברים - הוספה בודדת (שם+מייל) או **העלאת קובץ אקסל** עם רשימת שם/מייל, כולל **שליחת מייל הזמנה מעוצב בפועל** (SendGrid) עם קישור הצטרפות אמיתי (`/join?token=...`)
- התראת מייל אוטומטית לחברי פורום (שסימנו זאת) על תגובה חדשה
- לחיצה על **F8** בכל מקום באתר פותחת תיבת קוד סודית (לא מופיע שום רמז בממשק לפני כן).
  קוד נכון (מוגדר ב-`ADMIN_CODE` בקובץ הסביבה) פותח את **ממשק הניהול**:
  - סטטיסטיקה חיה: משתמשים רשומים, מחוברים כרגע, מס' פורומים, מס' חברויות
  - רשימת כל הפורומים כולל הסגורים לחלוטין, עם אפשרות לחסום/לשחרר כל פורום
  - רשימת משתמשים עם אפשרות לחסום/לשחרר משתמש
  - ניהול פרסומות: העלאת תמונה/וידאו (או קישור), תצוגה מקדימה, אישור/דחייה/הסרה
- ניווט ללא רענון עמוד מלא (Next.js client-side navigation + fetch), בהתאם לבקשה לחוויית שימוש זורמת

## מה עדיין דמה / דורש חיבור לשירות אמיתי

הדברים הבאים **כתובים ומוכנים במבנה הנכון**, אבל מסומנים בקוד עם `TODO` כי הם דורשים
מפתחות API שלא יכולתי ליצור עבורך:

| פיצ'ר | קובץ | מה חסר |
|---|---|---|
| שליחת מייל הזמנה בפועל | ✅ **מחובר בפועל** - `lib/email.ts` + `app/api/invites/` | רק צריך SENDGRID_API_KEY + EMAIL_FROM |
| התראת מייל על תגובה חדשה | ✅ **מחובר בפועל** - `app/api/threads/[id]/posts/route.ts` | אותו דבר |
| התחברות עם Google | ✅ **מחובר בפועל** ב-`app/api/auth/google/` | רק צריך למלא GOOGLE_CLIENT_ID/SECRET + NEXT_PUBLIC_APP_URL בסביבה |
| בסיס נתונים אמיתי (לא נמחק בכל הפעלה) | ✅ **מחובר בפועל** - `lib/store.ts` דרך Prisma | רק צריך DATABASE_URL (בריילוואי - Add PostgreSQL, זה אוטומטי) |
| אחסון קבצי פרסומות בענן | `app/api/ads/upload/route.ts` | שירות כמו S3 / Cloudinary / Vercel Blob (כרגע נשמר מקומית בשרת - עובד, אבל לא מומלץ בקנה מידה גדול) |

כל אחד מהם מתועד בהערת קוד (comment) בקובץ הרלוונטי עם הסבר מדויק מה להוסיף.

## מבנה הפרויקט
```
app/                  עמודים ו-API routes (Next.js App Router)
  page.tsx            עמוד ראשי
  login/               הרשמה/התחברות
  profile/             פרופיל אישי
  forum/[id]/          עמוד פורום בודד
  api/                 כל נקודות הקצה (auth, forums, threads, invites, admin, ads)
components/            רכיבי React (עורך טקסט, מודל יצירת פורום, פאנל ניהול וכו')
lib/
  store.ts             "בסיס נתונים" זמני בזיכרון - כאן שולבת כל הלוגיקה
  session.ts           התחברות משתמש רגיל
  adminSession.ts       לוגיקת קוד המנהל וה-F8
prisma/schema.prisma   סכמת בסיס הנתונים האמיתית, מוכנה למעבר מ-store.ts
```

## בסיס הנתונים - כבר מחובר בפועל
`lib/store.ts` עכשיו עובד מול Postgres אמיתי דרך Prisma (לא מערך בזיכרון יותר).
נבדק בפועל מול Postgres מקומי - הרשמה, יצירת פורום, שרשורים והזמנות נשמרים ונשארים.

**בריילוואי זה כמעט אוטומטי לגמרי:**
1. הוסף PostgreSQL לפרויקט (+ New → Database → Add PostgreSQL)
2. ריילוואי מזריקה אוטומטית `DATABASE_URL` לאפליקציה
3. בכל `npm run start`, הסקריפט מריץ קודם `prisma db push` שיוצר/מעדכן את הטבלאות
   בבסיס הנתונים לפי `prisma/schema.prisma` - אין צורך בשום פעולה ידנית

להרצה מקומית עם Postgres אמיתי (לא sqlite): הרם Postgres (למשל דרך Docker), הגדר
`DATABASE_URL=postgresql://user:pass@localhost:5432/dbname` ב-`.env.local`, ואז
`npx prisma db push` פעם אחת כדי ליצור את הטבלאות.

לניהול שינויי סכמה מבוקר יותר בעתיד (עם היסטוריית migrations, מומלץ לצוותים גדולים
יותר) - אפשר להחליף בהמשך את `db push` ב-`prisma migrate dev` / `migrate deploy`.
